# void-config

Sway-based Wayland desktop configuration for Void Linux (glibc, x86_64).
The repository holds every managed dotfile; `install.sh` reproduces the full
setup — packages, services, symlinks, login manager, fonts — on a fresh
Void installation.

## Requirements

- Void Linux (glibc) x86_64, base install with network access
- A non-root user with `sudo` or `doas` rights (`usermod -aG wheel <user>`)
- Git: `xbps-install -Sy git` (the installer covers everything else)

## Quick start

```sh
git clone https://github.com/rajan9884/void-config.git ~/void-config
cd ~/void-config
./install.sh
```

Partial runs:

```sh
./install.sh --packages-only   # XBPS packages + services only
./install.sh --links-only      # (re)create symlinks only
./install.sh --no-fonts        # skip the Nerd Font download
./install.sh --no-wallpapers   # skip the wallpaper collection download
```

Reboot after the first run so group membership (`input`, `video`) and the
greetd login manager take effect. Log in through tuigreet, select the
Sway session, and the desktop starts.

## What the installer does

1. **Packages** — syncs repositories and installs every entry in
   `packages.txt` (window manager, terminal, launcher, bar, audio,
   portals, CLI tools, fonts, build toolchain). The list is generated
   from the reference machine's explicitly installed set, so it stays
   free of auto-installed dependencies.
2. **Services** — enables `NetworkManager`, `bluetoothd`, `chronyd`,
   `cronie`, `dbus`, `greetd`, `polkitd`, `power-profiles-daemon`,
   `rtkit`, `ufw` (plus `warp-svc` when Cloudflare WARP is present).
3. **Login manager** — writes `/etc/greetd/config.toml` (tuigreet on VT7
   with the Sway Wayland session) and ensures the `wheel` sudoers entry.
4. **Dotfiles** — symlinks each tracked directory into `~/.config`,
   shell startup files into `$HOME`, and every script in `bin/` into
   `~/.local/bin`. File links whose parent directory already links into
   the repo are skipped, so a re-run can never write into the repo itself.
   Pre-existing files are moved to `~/.config-backup-void-<timestamp>/`,
   never deleted.
5. **Shell** — sets zsh as the login shell; zsh starts Sway
   automatically on TTY1 via `shell/zprofile`.
6. **Fonts** — downloads JetBrainsMono Nerd Font and NerdFontsSymbolsOnly
   into `~/.local/share/fonts` (skipped if already present).
7. **Wallpapers** — clones the
   [wallpapers](https://github.com/rajan9884/wallpapers) collection,
   flattens every image into `~/.local/share/wallpapers` (existing
   files are kept, the clone is deleted), and seeds the matugen theme
   from a random wallpaper when no theme exists yet.
8. **Directories** — creates `~/.local/share/wallpapers` and `~/.cache`.

The script is idempotent; re-running it repairs anything missing.

| `xdg-desktop-portal/` | `~/.config/xdg-desktop-portal` | Portal backend preferences |

Generated files (`sway/colors`, `waybar/colors.css`, `starship.toml`,
wallpaper pointer, etc.) are git-ignored; the templates under
`matugen/templates/` are the versioned source they are rendered from.

## Theming pipeline

Wallpaper drives the theme. `sway/scripts/sway-wall.sh <image>` records
the wallpaper, stages the lock-screen background, and runs matugen, which
recolors Waybar, Rofi, Foot, Sway, SwayNC, SwayOSD, GTK, and Starship in
one pass. Related helpers: `wall-selector`, `random-wall.sh`,
`init-wallpaper.sh` (restores the last wallpaper at login).

## Post-install steps (not scripted)

These depend on personal accounts or third-party binaries:

- **Wallpaper** — already seeded by the installer (collection + random
  pick). To switch later, copy images to `~/.local/share/wallpapers`,
  then run `~/.config/sway/scripts/sway-wall.sh <image>`.
- **Zen Browser** — build the `zen-browser-bin` AUR package with
  [vay](https://github.com/rajan9884/vay), then install the resulting
  `xbps` package from the local repository.
- **Cloudflare WARP** — convert the official `.deb` with `xdeb`, install
  it, then `doas ln -s /etc/sv/warp-svc /var/service/`.
- **GitHub** — `gh auth login`, then per repository run `git-work`
  (work identity, `rj9884`) or `git-personal` (`rajan9884`) from
  `zsh/git-accounts.sh` to set the local identity and SSH remote.
- **SSH keys** — add work and personal keys with host aliases
  `github-work` / `github-personal` in `~/.ssh/config` to match the
  helper script.

## Shell notes

- Both bash and zsh share aliases and guarded tool initializations; a
  missing tool is skipped silently so the shell starts clean mid-install.
- zsh plugins (`zsh-autosuggestions`, `zsh-syntax-highlighting`) are XBPS
  packages sourced from `/usr/share/zsh/plugins/`.
- `y` (yazi directory tracking), `z` (zoxide), `ff` (fzf file preview),
  and Atuin history (`Ctrl-R`) are configured in both shells.
- Login shells show `fastfetch` once; subshells skip it for speed.

## Troubleshooting

- **No graphical login**: check `greetd` with
  `doas sv status greetd` and confirm `/etc/greetd/config.toml` exists.
- **Sway cannot start**: verify user is in `input` and `video` groups
  (`groups`), then re-login.
- **No audio**: check `pipewire` and `wireplumber` processes and
  `wpctl status`; the tuned profiles live in `wireplumber/`.
- **Theme not applied**: run `sway-wall.sh` manually with an image path
  and confirm `matugen` is installed.
- **Installer overwrote a file**: originals are preserved under
  `~/.config-backup-void-<timestamp>/`.
